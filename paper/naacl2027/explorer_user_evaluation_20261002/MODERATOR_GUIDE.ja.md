# 実施担当者専用

参加者には`PARTICIPANT_GUIDE.ja.md`と確定済み同意書、自分用のリンクだけを渡す。**正解ファイル・この担当者ガイド・他参加者の割当は渡さない。**

## 開始前

1. `STATUS.json`が計画段階であることを確認する。倫理手続の確認、同意書の未確定箇所、実施者の準備が終わるまで募集・実施しない。確認のためのAI操作は人の回答に数えない。
2. 同じPC・ブラウザ・表示サイズを基本とし、版を記録する。`assignments.csv`の公開URLが実際に動くか確認する。公開前は同CSVのlocalhost版を使えるが、実施条件を混ぜない。
3. 両UIのデータが同じこと、SHA-256検証、全パネル情報、検索・展開・保存が使えることを確認する。モデルをロードしない。セッション中はUIを更新しない。
4. CSVの空欄テンプレートを作業用にコピーする。既存の空欄を成果件数に数えない。

## 進行

同意を確認し、任意の開発経験区分と以前の利用経験を記録する。ExplorerとJSONの選択欄、保存、全体情報の位置を同じ長さで説明する。実験ケースの数値や正解を先に説明しない。P01/P02を参加順に割り当て、指定順で開いてもらう。P01はExplorer、P02はJSONから始まる。ケース順は共通の固定順であり、無作為化された調査とは称さない。

操作を中立に見守る。「違います」「ここを見れば正解です」と誘導しない。質問には用語・操作について答え、支援内容を残す。未完了も結果。画面が壊れた場合は技術的問題として分ける。ZIP出典は基本課題で場所と値を見つければよく、アーカイブの実展開は任意の追加記録とする。6ケース後、各UIの難しさと自由記述を尋ねる。

## 正解と採点

担当者だけが使用する正解：
`../workflow_comparison_20261002/tasks.json`の`tasks[].expected_answers`。

凍結タスクSHA-256：`d629475e55bdc8c5d35cfb813a982925e65485a6a21b27d0a34e0c4fefc829a7`。

- 設問IDは空欄CSVと正解キーで一致する。`source_trace`は基本課題の出典発見と、任意の原ZIP実照合を区別して採点する。
- `physical_call_accounting`の共有数・和集合、Scoreの期待値・最頻段階・連続参照値を混同していないか確認する。
- `full_panel_distribution`は全200件。単一ケースを全体の分布と解釈した回答はその誤解として残す。
- 表示桁に沿った丸めは正答として扱い、判断基準を記録する。元データ破損と表示丸めを混同しない。
- 複数項目の一部だけ正しければ「一部正しい」。単純な正誤合計だけで隠さない。

採点は実施後に行い、原文回答を残す。独立採点がなければ担当者採点と記す。結果の改善案は観察された具体的な誤解・操作につなげる。2名から優位性、利用者全体の成功率、速度改善、有意差を結論しない。結果ゼロの現時点では論文に「人で検証済み」と追記しない。
