\begin{abstract}
A changed language-model decision can correct an error, move probability mass, or hide a stable but degenerate predictor. \system{} connects semantic candidate comparisons, panel-level outcomes, and source-record and physical-call provenance. A local API returns typed values from frozen next-token logits; a model-free browser exposes saved panels, while a separate importer compares users' physical records. Direct readout and native one-token decoding agree in all 1,350 matched pairs without an established latency advantage. Presentation and averaging studies use 22,000 calls: reduced sensitivity can accompany incorrect or nearly constant predictions. Further Japanese/English experiments do not establish added error-detection value from order sensitivity. These observations motivate displaying correctness, diversity, and cost alongside stability. Complete-JSON and ChainForge reconstructions retain equivalent diagnostic evidence. We contribute an auditable inspection workflow and scoped system evaluation; improved human performance remains untested.
\end{abstract}

\section{Introduction}
Applications may need a route, an urgency score, or a rubric stage. Typed interfaces make these contracts explicit, but valid types and concentrated candidate probabilities do not establish correct decisions.

\system{} (formerly Mini Jev) demonstrates this distinction through a local browser interface, an HTTP/Python API, and a saved-evidence explorer. Users can run typed questions locally or inspect recorded comparisons without downloading a model. The interface is inspired by TypeSafe's Jev \citep{typesafe2026jev,typesafeapi}; this independent implementation does not reproduce its architecture, training, calibration, compatibility, or performance.

NLP developers comparing configurations need to determine which semantic probabilities changed, whether that corrected an error or hid a degenerate predictor, and which executions support the comparison. We connect aligned distributions, reference outcomes and panel frequencies, and source/call provenance to answer these questions. Complete JSON and custom ChainForge workflows retain equivalent evidence; evaluation establishes reconstruction and failure visibility, not faster human diagnosis. Candidate scoring and typed probability interfaces are established \citep{schick2021pet,ma2025inferring,lmqlscoring}; our contribution is their inspectable evidence path.

\section{System and Typed Contract}
\label{sec:system}
\subsection{From a state to typed values}
A request contains a shared \texttt{state} and named questions. Each question supplies a type, natural-language instructions, and candidate criteria. The service returns a semantic label, a candidate distribution, and a type-specific value:
\textbf{Choice} returns the most likely candidate's key; keys are canonically sorted before prompting. \textbf{Noul} returns the true-candidate probability in a false/true decision. \textbf{Score} returns the expected zero-based rubric stage, alongside its most likely stage label.
A Score expectation of 1.6 on stages 0--3 is a probability-weighted position, not a generated stage or calibrated utility. Interpretation assumes equally spaced stage indices.

Let $z_i$ denote the next-token logit for candidate $i\in\{0,\ldots,K-1\}$, with $K$ candidates and temperature $T>0$. The service computes
\begin{equation}
\begin{aligned}
 p_i &= \frac{\exp(z_i/T)}{\sum_{j=0}^{K-1}\exp(z_j/T)},\\
 s &= \sum_{i=0}^{K-1} i p_i.
\end{aligned}
\end{equation}
These are probabilities conditional on the selected candidate set. They are neither probabilities over all valid textual answers nor guarantees that the criteria are exhaustive. Changing the criteria changes the question as well as the normalization. The optional scalar temperature preserves the maximum-logit label, but can change Noul and Score values.

The interface also displays entropy concentration,
\begin{equation}
\begin{aligned}
 c &= 1 - H(p)/\log K,\\
 H(p) &= -\sum_i p_i\log p_i.
\end{aligned}
\end{equation}
A concentrated distribution has $c$ near one. The display identifies this quantity as concentration rather than estimated accuracy. The response includes probability-semantics and calibration metadata, so downstream applications can retain the same distinction.

\subsection{Local execution}
The released inference configuration uses Qwen3.6-35B-A3B in Q4\_K\_M GGUF form \citep{qwen36,qwen36gguf}, through a source-built \texttt{llama.cpp} helper \citep{llamacpp}. The model and its output projection remain frozen; there is no trained decision head. The helper performs the full vocabulary projection and then gathers candidate logits. It does not implement a selected-row projection optimization.

The prompt repeats the task twice, following the use of repetition for non-reasoning inference \citep{leviathan2025repetition}. Choice and Noul use letter labels; Score with at most ten stages uses digits after a prefilled answer-object prefix. Larger Score rubrics use letters. The implementation checks that every candidate is a distinct single token at the actual prefix boundary. The API accepts 2--26 candidates; quality evaluation covers 2--8, while larger candidate sets have functional coverage only.

A multi-question request executes its questions sequentially. Model state is cleared between questions: they share the supplied state text, but not a cached prefill. Complete inputs exceeding 2,048 tokens are rejected rather than silently truncated. Schema validation and deterministic response construction prevent free-form output from crossing the API boundary; these software properties do not prevent semantic errors.

\subsection{Relationship to one-token decoding}
Readout and candidate-masked one-token decoding have the same distribution when prefix, logits, candidate IDs, temperature, and processors match. Greedy labels agree except for tie-breaking; stochastic samples need not match. Choosing the first token after prefill need not require another forward pass, so avoiding generation does not itself imply a speedup. Section~\ref{sec:evidence} tests an actual native sampler under matched conditions.

\section{Demonstration and Access}
\label{sec:demo}
\subsection{Inspect saved evidence without a model}
The static \ExplorerURL{} requires only a browser. It contains all eligible records from the presentation and averaging studies: 22,000 physical calls and 9,000 derived answers in 18 panels. Their 3,600 study/item/model combinations represent 1,200 distinct source items, reused across checkpoints. These are recorded observations, not new inference.

Users choose a study, checkpoint, task, item, and two conditions. Both sides retain the same item and model; probabilities align by semantic key on a common 0--100\% scale even when token bindings or row order differ. The display separates the selected label, typed value, concentration, and reference. Full-panel label frequencies remain visible independently of item selection. This permits inspection of an order flip, a correct answer lost after averaging, or a nearly constant predictor. Four outcome-selected examples illustrate these cases; they do not estimate prevalence.

The explorer also distinguishes executions from derived results. An averaged answer lists its physical members; comparisons count their union without double-counting shared calls. Source details identify archive members, JSONL lines, mappings, and hashes. Loaded panels are SHA-256 checked; comparison exports retain exact values and sources. Original task text is withheld. URL fragments share selections. Software checks match all exported records, 172,200 dependent comparison pairs, and 155 panel distributions to raw calculations. A complete-JSON view retains the same information; these are not human-performance results.

A separate \href{https://uphash-network.github.io/mini-jev/explorer/import/}{local JSONL importer} aligns user-supplied physical logits or declared full probabilities and exports typed comparisons without uploads or storage. Missing references/latency remain unknown; source authenticity and derived-member recipes are unsupported. Synthetic tests and one hash-selected archived item check compatibility, not practical advantage.

\subsection{Run local typed decisions}
The separate live browser connects through a Python bridge to the local model API. Users edit a shared state, instructions, and criteria for Choice, Noul, and Score, then select \emph{Run decisions}. Results expose candidate probabilities, concentration, elapsed time, and request/response JSON. Editing marks prior results stale. The live UI has no replay or cyclic-averaging mode: an unavailable API produces an error. Input edits explore behavior, not controlled accuracy.

A linked \href{https://github.com/UpHash-Network/mini-jev/blob/research/naacl2027-demo/paper/naacl2027/reviewer_20261002/README.md}{reviewer guide} proceeds from the explorer to model-free verification and optional live installation. The tested live environment is a 64\,GB Apple M5 Pro; its model file is approximately 20.4\,GB. Appendix~\ref{sec:comparison_scope} gives installation and verification boundaries. The static explorer has no model, API-key, or build requirement.

\subsection{Matched runtime and parity}
All three conditions used one resident model and a common research HTTP response containing a type and semantic label. Direct readout and native one-token greedy selection used identical complete prompts and candidates. The JSON condition actually generated a grammar-constrained object, with a serialization-specific prompt. Its timing comparison therefore includes prompt and prefill differences as well as multi-token generation; it does not isolate sampler overhead.

All $(150\times5+600)\times3=4{,}050$ requests completed without recorded failures; 21 synthetic warm-ups are excluded. Mode order was randomized within item/repetition. Research-harness timing spans serialization through loopback HTTP parsing, including audit transfer but excluding trace writes and browser rendering.

Direct and one-token conditions matched prompts, token sequences, candidate IDs, logits, and labels in all 1,350 paired observations. Maximum observed candidate-logit difference was zero; there were no maximum-logit ties. The primary latency statistic is the median across 150 local items of the within-item difference between five-repetition mean latencies. It is not a difference between marginal medians.

\subsection{External task-specific results}
Direct readout and one-token selection have identical external labels. JCoLA reached 86.0\% accuracy and MCC 0.5708; JSON reached 82.0\% and MCC 0.5160. The selected sample contains 158 acceptable sentences, so an always-acceptable rule already achieves 79.0\% accuracy and has undefined MCC. Reporting only accuracy would obscure this imbalance.

JCommonsenseQA accuracy was 95.0\% for direct/one-token and 95.5\% for JSON, a difference of one example. JSTS retains its continuous reference scores in $[0,5]$: direct expected-stage MAE at $T=1$ was 0.5065. JSON has no comparable probability vector, so we do not assign it an expected-stage metric. The separate hard-stage comparison gives MAE 0.5480 for direct/one-token and 0.5650 for JSON. We neither round gold scores into classes nor pool task metrics.

\subsection{Presentation sensitivity and averaging}
Two subsequent studies add Qwen2.5-0.5B-Instruct and Qwen2.5-1.5B-Instruct to the native 35B checkpoint. The first uses 7,600 requests on the same 600 external items. All 1,800 exact-input repeat pairs have identical logits and probabilities, yet display reversal changes native JCQA labels on 11/200 items. Conversely, the 1.5B checkpoint has zero JCoLA flips while always predicting acceptable: stability alone is insufficient.

The second freezes 600 additional public-development items before its 14,400 requests. It excludes prior IDs and literal text reuse, and selects JSTS pairs from previously unused sentence/image components. However, 194/200 JCoLA items share bibliographic sources with earlier evaluations. Both studies complete without inference errors; each excludes 57 synthetic checks/warm-ups.

We average semantic candidate probabilities at $T=1$ across cyclic rotations of complete option lines, keeping output-token--meaning bindings fixed. Fixed-binding transformations and cyclic aggregation have precedent \citep{wei2024unveiling,zheng2024selectors}; this is not a new algorithm or a reproduction of PriDe. Table~\ref{tab:orientation} compares canonical-single and forward-cyclic accuracy, alongside single/reversed and forward/reverse-cyclic label disagreement. Lower disagreement does not consistently improve accuracy. The 0.5B cyclic JCoLA output is always acceptable (78.5\% accuracy, undefined MCC). On JSTS, 0.5B and 1.5B cyclic hard labels occupy one stage on 199/200 and 200/200 items, respectively. These marginals expose collapse hidden by type validity or stability.

One cyclic answer costs 2, 5, or 6 model calls for JCoLA, JCQA, or JSTS; the single baseline reuses a pool member. Binary forward/reverse pools contain the same two calls, so their equality is structural. There is no equal-call repeat control in this averaging study. The small checkpoints use Transformers/MPS float32; the native model uses quantized Metal inference. Architecture, precision, and backend differ, precluding a model-size or cross-backend speed conclusion. These are descriptive system checks; fuller distributions, grouped intervals, and call accounting accompany the artifacts.

\paragraph{Diagnostic value.}
A frozen 240-question JCQA panel adds 2,400 calls across Qwen 1.5B and 35B; adding order-induced total variation (TV) to entropy did not establish added error-detection value. A scope extension adds 4,800 calls on 240 new JCQA and 240 English CommonsenseQA items \citep{talmor2019commonsenseqa}, shared by Qwen 1.5B and Phi-4-mini \citep{microsoft2025phi4mini}. Its primary Phi-English AP difference is $-0.051$; at 720 calls, both policies return 174/240 correct answers. All intervals and budgets are retained (Appendix~\ref{sec:comparison_scope}). A post-hoc aggregation control on the same extension responses changes 4--8 labels per 240 items between arithmetic and geometric means, without consistent accuracy gains (Table~\ref{tab:aggregation}). Sensitivity remains an inspection signal, not a confidence or routing guarantee.

\subsection{Reproduction and framework integration}
The original package retains 26,050 requests, protocols, hashes, and analyzers. Clean-directory CPU replay reproduced 56 derived files byte-for-byte. A fresh native build served all three types with a cached, hash-verified model on the same Mac: source/cache reconstruction, not independent-machine replication.

Synthetic integration checks retain failures. With matched checkpoint, prefixes, and candidate IDs, a custom LMQL 0.7.3 backend matched 12/12 labels, but three probability differences exceeded $10^{-5}$ (maximum $2.63\times10^{-5}$). ChainForge's custom provider preserved eight typed-answer pairs and rejected three invalid inputs. These are interoperability checks (Appendix~\ref{sec:comparison_scope}), not human or quality evaluations. A retrospective engineering case also retains a failed numerical gate, its amendment and subsequent measurements; exact distributions reveal discrepancies hidden by matching labels.

\section{Related Work and Scope}
\paragraph{Candidate and ordinal scoring.}
Verbalizers \citep{schick2021pet}, decoding-free selection \citep{ma2025inferring}, Qwen3 reranking \citep{zhang2025qwen3embedding,qwen3reranker}, and G-Eval's weighted scores \citep{liu2023geval} precede our readouts. Expected ordinal relevance appears in zero-shot ranking \citep{zhuang2024beyond} and trained job-candidate scoring \citep{wang2026singletoken}. We claim neither a new scoring rule nor ranking gains.

\paragraph{Structured interfaces.}
LMQL scores continuations \citep{lmqlscoring}; Outlines, Guidance, and grammars constrain generation \citep{outlines,guidance,geng2023grammar}. TypeSafe's adapter returns generated rather than candidate-logit probabilities \citep{typesafeadapter}. Native \texttt{llama.cpp} source serves supported decision models, including LEV order averaging, not arbitrary GGUF models \citep{llamacpp2026systemone}. LLM2Jev scores complete bracketed numeric suffixes on frozen backbones and separately studies fine-tuning \citep{li2026llm2jev}; this differs from one-token readout. AnyJev studies label-prior correction and log-space cyclic aggregation with position-bound labels \citep{zhang2026anyjev}; we retain fixed token--meaning bindings. OmniMed-Jev trains a medical multimodal candidate head with LoRA \citep{tang2026omnimedjev}; AudioJev trains supervised audio order consistency \citep{lv2026audiojev}. Our serialization and aggregation checks do not benchmark these systems.

\paragraph{Inspection interfaces.}
Rakutko's distinct mini-jev compares frozen letter-logit scoring with constrained JSON in an inspection bench \citep{rakutko2026minijev}; our rename avoids confusion. Ollama documents local Choice/Noul/Score probabilities \citep{ollama2026decision}; ChainForge adds an Ollama decision provider \citep{arawjo2024chainforge,chainforge2026decision}. Its inference path remains untested here. ChainForge 0.3.7.6's GUI retains six matched saved-evidence cases; its native Processor also executes our custom JavaScript to reconstruct 2,400 conditions from 6,000 archived logit records within $10^{-12}$ tolerance. This supports competitor feasibility, not inspection superiority (Appendix~\ref{sec:comparison_scope}). LLM Comparator compares responses \citep{kahng2025comparator}; Langfuse and Phoenix expose typed distributions or metadata \citep{langfuse2026jev,phoenix2026jev}. New promptfoo source retains Jev answers in regular and rubric evaluation paths \citep{promptfoo2026typesafe}; these source integrations are untested here. Our distinction concerns connecting complete panels, semantic alignment, shared calls, and archive-line provenance.

\paragraph{Sensitivity and calibration.}
Order/token bias and fixed-binding changes are established \citep{wei2024unveiling,zheng2024selectors}. Preprints separate order stability from accuracy \citep{hanna2026diverge}, ordinal hard-label collapse from concentration \citep{gao2026ordinal}, and correlated judge errors from confidence-cascade savings \citep{rao2026rubric}. SenSel uses bias-adjusted sensitivity to instruction or demonstration-order changes for abstention \citep{chen2023sensel}. Its perturbations and endpoint differ from our candidate-order TV; our nulls neither reproduce nor refute it. Temperature scaling \citep{guo2017calibration} differs from label-bias correction \citep{zhao2021calibrate}; canonical sorting does not establish invariance.

\section*{Limitations}
Presentation studies cover three checkpoints on one Apple Silicon device; matched parity/latency covers one native quantized model in one session. Architecture, precision, and backend differences prevent model-size attribution. Public subsets have unknown training contamination and source dependence. The English extension covers one five-choice task; model sizes and languages are confounded with family and dataset. Local data are AI-authored and development-related, without independent human reference validation. No user study establishes usability or downstream decision quality.

Candidate probabilities vary with prompts, labels, coverage, and temperature. Concentrated wrong answers occur; type validity and entropy concentration cannot replace application-specific validation before consequential actions. Score assumes equally spaced stages; Noul is a relative candidate probability, not a verified truth frequency. Questions run sequentially on a large model; other operating systems and lower-memory configurations remain unvalidated. Live-demo timings are not directly comparable with the research harness's controlled interval.

\paragraph{Public and internal inspection.}
The released HTTP response and browser expose semantic labels, typed values, candidate probabilities, concentration, and probability-semantics metadata. Raw candidate token IDs and logits belong to the internal engine and research traces; they are not fields in the public response. Table~\ref{tab:comparison_scope} distinguishes controlled comparisons, integration checks, and source-based related work. These observations do not establish that people work faster or make better decisions with this interface.

\paragraph{Model-free evidence review.}
The frozen source/evidence ZIP retains the original 26,050 measured requests; 300 earlier pilot predictions are background and excluded. Standard-library checks verify accounting, and CPU replay reproduces 56 derived files without models or network access. The current manuscript and later studies are separate packages. The explorer validates unchanged source hashes, semantic mappings and physical-call unions. Reanalysis verifies calculations, not observation authenticity or generalization.

\paragraph{Live installation.}
The reviewer guide supplies native build, pinned-model acquisition, and \texttt{./run.sh -{}-without-calibration} commands. Running \texttt{python3 -m demo.server -{}-port 8766} serves the interface at \url{http://127.0.0.1:8766/}. Fresh builds use $T=1$; historical calibration is runtime-bound. Tests use macOS 26.4, Metal, and Accelerate. The 20.4\,GB model requires additional runtime memory; a minimum configuration is unestablished. We distribute source, not weights or binaries. Serving \texttt{docs/} over HTTPS or localhost enables model-free browser hash verification.

\paragraph{Post-hoc LMQL diagnosis.}
All three original $10^{-5}$ probability failures remain. Maximum Score expectation error is $7.18\times10^{-5}$, within the separate $10^{-4}$ typed-value tolerance. Native probability margins exceed 0.9799, so matching labels provide no near-boundary evidence. Softmax of saved LMTP logits reproduces LMQL probabilities within $3.64\times10^{-9}$; native-path logit differences can account for discrepancies, but their cause remains unisolated. Type, candidate count, and prefix are confounded. This analysis adds no inference and changes no threshold.

All presenters receive complete panels and source indices. ChainForge's native search, lightboxes, spreadsheet and flow exports retain evidence supplied by the adapter, which computes alignment, deltas and call unions. No human performance was measured.

\paragraph{Reconstruction from raw records.}

\paragraph{Error detection and budgeted replay.}
