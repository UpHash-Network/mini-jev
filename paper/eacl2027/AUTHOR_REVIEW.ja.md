# EACL投稿前の著者確認

著者表記は **Yuki Oshio / UPHASH Inc. / oshio@uphash.net** の単著で確定済み。
この文書は確認用であり、確認・承認が完了したという記録ではありません。

## 論文で主張すること

- Mini Jevは、ローカル言語モデルの候補トークンのスコアを、Choice・Noul・Scoreの型付き応答として返し、その候補分布を調べられるシステムです。
- 最終構成の35Bモデルに追加学習はしていません。新しい学習アルゴリズムや、元のJevの内部実装を再現したという主張はしません。
- 同じ条件の直接読み出しと1トークン生成は1,350組すべてでlogits・選択ラベルが一致しました。150個のローカル問題に基づく主要な速度差の区間はゼロをまたぎ、明確な速度優位は示せませんでした。
- JSON生成との差は約160 msでしたが、出力指示も異なる比較です。すべてのモデルや環境でこの差が出るという主張ではありません。
- 型や値域が正しくても、意味的に正しい答えとは限りません。候補内の確率や分布の集中度を、正答率とは呼びません。

## 数値の読み分け

| 記録 | 実際の意味 |
|---|---|
| ローカル2,400問、93.25% | AIが作成した関連する問題群での指定ラベル一致率。独立した人手評価ではない |
| JNLI 300問、81.0% | 公開devから選んだ均等クラスの先行パイロット |
| 外部600問 | JCoLA・JSTS・JCommonsenseQAを各200問。分類と回帰を一つの正答率に合算しない |
| 4,050リクエスト | 一部ローカル問題の5反復と外部600問を3方式で実行した数。4,050個の独立問題ではない |
| 英語の実演例 | UIの動作説明。英語での精度を検証したベンチマークではない |

外部データも公開済みのため、モデルの事前学習との重複は不明です。評価環境は1モデル・1端末に限定され、matched比較は1セッションの観測です。

## 著者本人が最終稿で確認すること

1. 研究の動機・問い・貢献の説明が、自分の意図と一致しているか。
2. 上記の数値、式、限界、引用を理解し、必要な修正を原稿へ反映したか。
3. AIによるコード・データ・解析・草稿への支援を正確に開示しているか。
4. 他の査読付き媒体で同じ内容を審査中または採択済みにしていないか。
5. 投稿版のPDF・動画・コードの組合せを最終承認できるか。
6. EACLが求める著者査読担当候補の指定と、採択後の登録・実演に対応できるか。

最終承認の対象ファイル名・SHA-256は提出準備の検査記録に残します。
確認前に「本人が全て検証済み」と宣言したり、投稿画面の宣誓へ代理で回答したりしません。
