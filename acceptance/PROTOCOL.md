# 簡易Jevの受入評価仕様

この受入試験は、日本語の短い状態と明示的な選択肢・評価基準を渡す限定用途を対象とする。問題文に必要な情報を含め、医学・法律・外部の事実知識は要求しない。合格はこの手作り受入試験における機能の完成を示すもので、汎用能力、安全性、公式Jevとの同等性を保証しない。

## データの分離

- `private/acceptance_test.jsonl`: 独立執筆180件、Choice/Noul/Score各60件。
- `private/calibration.jsonl`: 確率調整専用120件、各型40件。受入データの言い換えを使わず、別の場面・評価基準を執筆した。
- 別途生成する2220件と手書き180件を合わせた2400件についても評価する。手書き180件の成績は必ず独立に表示する。
- 独立執筆者は既存の訓練・開発・評価データと結果を参照していない。本文・正解は、モデル・プロンプト・推論方式の選定から隔離する。
- 校正データで確率調整を行う前に、本体モデル、重み、プロンプト、候補の表し方、推論方式、校正手順を固定する。校正後、そのパラメータも記録してから受入試験を行う。
- テストの誤りを見て修正した版を同じ問題で測る場合は「既知の回帰試験」と明示する。新しい未見評価での合格とは呼ばない。

## 合否

予め固定した単一設定について、次の条件をすべて満たすことを完成の候補基準とする。

| 評価項目 | 基準 |
|---|---|
| 2400件のラベル正解率 | 90%以上 |
| 2400件の型別ラベル正解率 | Choice/Noul/Scoreそれぞれ85%以上 |
| 手書き180件のラベル正解率 | 162/180以上 |
| 手書き180件の型別正解率 | 各51/60以上 |
| Choiceの候補順変更後の意味ラベル一致率 | 90%以上 |
| 型・値域・確率分布の妥当性 | 100% |
| M5 Proでの単問応答時間p95 | 実際の入力が512トークン以下の対象で500ms以下 |

独立手書き問題のラベルは、問題中の情報と評価基準だけで確認した。未確認の情報を「いいえ」とするNoulには、その判定方法を質問に明示している。Scoreは曖昧な印象点を推測する方式ではなく、問題ごとの段階基準を選ぶ方式を中心とする。

## 各数値の意味

- **ラベル正解率:** 最大確率候補の`label`と正解の一致。Scoreの確率加重平均を丸めた値は、ラベル精度に使わない。
- **Score:** 候補の配列位置を0始まりの段階とする。`score = sum(index * probability)`。配列に記された数値や順位そのものを返すとは限らない。
- **Noul:** `noul`は`true`候補の確率。`label`は2候補の最大確率ラベル。
- **候補順変更:** Choiceのみを対象に、意味キーと説明の対応を保ち、初回と異なる順番を固定seedで作る。予測を英字トークンや表示位置ではなく、元の意味キーで比較する。一致率と、並べ替え後の正解率を両方示す。同じ誤答を維持するだけでも一致率は上がるため、一致率を精度とは呼ばない。
- **Scoreの順番:** 段階の順序自体が型の意味なので、単純に配列を並べ替えた問題は同じ問いではない。順序頑健性の受入母数から除外する。
- **Noulの順番:** 実装が`false/true`の順に正規化する場合、入力辞書の順番変更は推論入力を変えない。有効な候補順変更試験として数えない。
- **型妥当性:** 型に応じた必須フィールド、候補キー集合、有限で非負の確率、和が1、確率とのラベル整合性、Noulの値、Scoreの加重平均と範囲を確認する。推論例外も失敗として記録する。
- **遅延:** モデル読込・初回コンパイルを別に記録し、ウォームアップ後に単問で測る。バッチ時間を件数で割った値を単問遅延として使わない。必要な同期を含めた壁時計時間とし、対象件数・入力トークン数・中央値・p95・測定機器を併記する。512トークン超の問題は精度から除外せず、遅延の別集計とする。
- **校正:** 校正前後のNLL、Brier、ECE等を報告する。校正の有無と手法を明示し、単にsoftmaxを返すことを「正解する確率が校正済み」と説明しない。
- **集計:** 型別、手書き/生成別、family別、familyマクロ平均を併記する。生成問題はテンプレート内で相関するため、2400件を2400種類の独立能力と解釈しない。

## 運用上の制約

情報不足も判定させたいChoiceには、そのための候補を渡す。曖昧な入力でも許可候補のどれかの確率が大きくなるため、高い候補内確率だけで情報充足や実世界での確実性を保証しない。失敗した問題や性能限界は公開結果に残し、合格のために受入閾値や問題を後から変更しない。
